This reference describes dictionary authoring for the current Lua translator.
Paths below are relative to the repository root. Sources of authority are
`LTGOLD/dic.txt`, chapter 3 and appendix 1; actual CP866 records in
`LTGOLD/BASE.DIC`, `BUSINESS.DIC`, and `COMPUTER.DIC`; and the implementation in
`core/lexicon.lua`, `core/senses.lua`, `core/matching.lua`, `core/phrasing.lua`,
`core/agreement.lua`, and `core/generation.lua`. The curated greetings are in
`dictionary/pending.txt` (waiting to return to `dictionary/changes.txt`).

Examples labeled **historical** are dictionary encodings, not claims about a
captured translation. A tag's linguistic name does not prove every engine path
works correctly. **Internal**, **generated**, and **unresolved** mean exactly
that: do not turn them into new dictionary conventions without checking code and
behavior. Original translation claims still require the capture workflow.

Tags are ASCII Latin letters and are case-sensitive. Russian case letters and
payloads are Cyrillic, encoded as CP866 in `.DIC`. Do not substitute lookalike
Latin letters. Numeric suffixes are positional fields, not a universal paradigm
number: `X001` and `R011` have different layouts.

## Dictionary classes

The meanings in this table come from the manual unless a caveat says otherwise.
Historical examples are exact full entries or explicitly identified reading
fragments. Empty translations can be intentional for structural words.

| Code | Meaning and authoring use | Example and explanation |
| --- | --- | --- |
| `A` | Adjective or ordinal numeral. Use a Russian citation form for agreement. | Historical `economic*Aэкономический`. |
| `a` | Adjective/adverb subclass, such as more/less. Not an ordinary `A`. | Historical `least*aнаименееAнаименьший`; the entry carries both readings. |
| `B` | Infinitival `to`, associated with perfective aspect. Not auxiliary be. | Historical `in being able to*B`; historical `to` begins `B, чтобы` and also has `b.`. |
| `b` | Infinitival `to`, associated with imperfective aspect. | Historical `for the purpose of*bдля того, чтобы`. Grammar can change `bG` to `BV`. |
| `C` | Coordinating/disjunctive conjunction. | Historical `and*Cи`, `or*Cили`. |
| `D` | Adverb, parenthetical word, or fixed adverbial expression. | Manual `economically*Dэкономически`; greeting component `Dкак`. |
| `d` | Adverb/adjective ambiguity. | Historical `faster*dболее быстроA.WDболееAбыстрый`; context selects the reading. |
| `E` | English -ed or irregular past/participle forms; may also carry adjectival readings. | Manual `crossed*Eпересекать\cross`. `E` alone does not mean a resolved passive participle. |
| `e` | Coincident infinitive, past, and/or participle-II forms. | Manual `read*eчитатьNчтение`, `come*eприходить`. |
| `F` | Manual: active present participle, generated by analyzer. **Implementation caveat:** historical entries also use it for irregular forms; the lexical decoder converts initial `F` to `E`, sets past tense and marker `n`. | Historical `chosen*Fвыбирать\choose`. Do not infer output tense from the manual's label alone. |
| `f` | Determinative expression followed by a noun phrase. | Historical `does it take*fпотребуется`; `are` has secondary `fесть ли`. Not a participle. |
| `G` | English -ing form, potentially verb, gerund, noun, or adjective. | Manual `interfacing*GсвязыватьNсопряжение\interface`. |
| `H` | Digits and combinations classified by the tokenizer. | Input token `123` is `H`. Usually generated rather than authored as `123*H...`. |
| `I` | Numeral/quantity word. Ordinals can instead be `A`. | Historical `a lot of*I1много`; `1` is number metadata. |
| `J` | Conjunction or phrase-separating word. | Historical `albeit*Jхотя`; authored empty `J0` in the greeting separates case-government groups. |
| `K` | Negative particle not. | Historical `not*KнеDнет`. |
| `k` | Negative particle no and related negative expressions. | Historical `by no means*kникоим образом`; the word `no` itself has several historical readings, so do not invent `k` as its only code. |
| `L` | Relative word meaning “, который”. | Historical `all of which*L, который`; `who` also has `L, который`. |
| `l` | Movable relative/possessive word meaning “чей”; manual calls it analyzer-generated. | Historical `whose*Qчейlкоторый` contains an `l` reading. |
| `M` | Oblique/object pronoun; defaults to genitive during lexical decoding. Grammar can change its case. | Historical `me*M011я`, `him*M031он`. Store the lemma, not a frozen object form. The native greeting below instead uses an empty composite component on an existing node with complete pronoun fields. |
| `m` | Compound oblique pronoun. Initial `m` normalizes to `M`, but has no `M`-style digit decoder or automatic genitive assignment at that point. | Historical fragment `mему` in `he*R031онrу негоmему`. |
| `N` | Singular noun/citation noun reading. Number can subsequently change through agreement. | Manual `economy*Nэкономика;экономия`. |
| `n` | Plural noun form, normally with the singular Russian lemma as payload. Normalized to runtime `N` with plural number. | Manual `accessories*nпринадлежность`; greeting `nдело` generates plural `дела`. |
| `O` | Demonstrative/determining pronoun category. | Historical `our*Oнаш`; `this` has `Oэтот`. The manual does not fully distinguish all `O` and `S` uses. |
| `P` | Preposition, optionally governing a Russian case. | Historical `across*PВчерез`; `В` means accusative. Greeting `PР01у` governs genitive. |
| `Q` | Question word. | Historical `how*QкакJкак`; `who` begins `Qкто`. |
| `R` | Personal pronoun. Supplies number/person/gender for normal inflection. | Historical `he*R031онrу негоmему`; curated `you*R021ты`. |
| `r` | Compound personal pronoun. May represent the possessor in an existential construction; initial lexical `r` normalizes to `R`, while grammar can create runtime `r`. | Historical `i*R011яrу меняmмне` and `we*R11мыr11у насmнам`. |
| `S` | Demonstrative pronoun category, also used for substantive pronoun readings. | Historical `this*SэтоOэтот`, `all*S1всеOвесьDполностью`. Do not assume a universal standalone/attributive split from `O`. |
| `T` | Determiner/article, often silent in Russian. | Historical `a*T`, `the*T`. The tag is structural, not a general deletion instruction. |
| `t` | Segment-boundary determiner, generated by grammar. | `core/phrasing.lua` handler 1 inserts a `t` boundary with separator `\|`. Do not author an ordinary word as `t` without a specific reason. |
| `U` | Modal verb. | Historical `can*Uмочь`; `must` begins `Uдолжен`. |
| `u` | Modal verb combination. | Historical `be deemed to*uсчитается, что`. |
| `V` | Main/content verb, normally supplied as a Russian infinitive. | Manual `economize*Vэкономить`. Finite form comes from grammatical state and morphology. |
| `v` | English -s/-es verb form. Normalized to `V` with third person. | Manual `adds*vдобавлять`; the manual also allows `adds*vдобавляет`, but prefer lemma-based generation for reusable rules. |
| `W` | Composite Russian equivalent containing tagged components. It is a reading marker, not an “any word” class. | Historical `after-sale services*WAпослепродажныйNсервис`; greeting `WDкакnдело`. |
| `X` | Auxiliary be, including am/are/is and tense auxiliaries encoded this way. | Historical `am*X001\be`, `was*X103бытьx1быть\be`, `will*X203быть`. |
| `x` | Impersonal verb combination. | Historical `need*xнужноNнеобходимость`; `was` has secondary `x1быть`. Not interchangeable with `X`. |
| `Y` | Auxiliary have, with possessive reading “иметь”; also participates in perfect constructions. Lexical default case is accusative. | Historical `has*Y003иметьyесть\have`, `have*Yиметьyестьx1быть`. |
| `y` | Auxiliary/existential have with reading “есть”; often existential/negative constructions. Defaults to genitive; optional digit sets `aspect`. | Historical `there is*yесть`; `do not have` includes `y1нет`. Not lowercase spelling of `Y`. |
| `Z` | Ambiguous V/N/A word: verb reading first, followed by available noun/adjective readings. | Manual `work*ZработатьNработаAрабочий`. Not every `Z` must have all three. |
| `z` | Ambiguous -s verb/plural noun (v/n). Decoder sets plural number and third person, then normalizes to `Z`. | Historical `accesses*zуправлятьnдоступ\access`. |
| `#` | Nontranslated unit, proper name, or designation; optional number/gender allow agreement. | Manual `brown*#0м`; historical `abbott*#0м=` requests transliteration. Not the ordinary class for fixed Russian prose: the decoder takes a leading с/м/ж as gender, so `W#согласно#` printed `огласно`. |
| `\|` | Fictitious separator class; also has other meanings inside verb readings. | Historical `as many as*\|столько, сколько`. In a tag pattern, `\|` is a literal separator tag, not alternation. |

## Internal tags

These complete the alphabetic inventory actually handled or emitted by the Lua
pipeline beyond the manual's ordinary dictionary classes. Some also occur in
historical dictionaries; presence alone does not establish their full meaning.

| Tag | Established behavior and example | Authoring boundary |
| --- | --- | --- |
| `c` | Historical `rather than*c, а не`; grammar uses it in coordination-related contexts, e.g. pattern `O[&c]I`. Verified against `C`: `I walk rather than run` gives `а не бежать` with `c`, `а не бегу` with `C`. | Use `c` for a comparative/contrastive conjunction whose following verb must not become a coordinated finite verb. |
| `g` | Historical `including*gвключать\include`; T1 changes `*GPH,[TORS]` to `@gPHj`. Verified: `Ten cats came, including him` gives adverbial participle `включая` with `g`, finite `включают` with `G`. | Preposition-like -ing word rendered as an adverbial participle. Do not convert ordinary `G` readings. |
| `h` | Historical `ate*hесть\eat`, `became*hстановиться\become`. Lexical decoder sets past tense and normalizes initial `h` to `V`. | Irregular-past input code; not an ordinary present verb. |
| `i` | Historical `great deal*iмного`; grammar produces `i` with `HCa` → `@@i` and `aN` → `i`. Verified: `A great deal was done` gives singular `Много был сделан` with `i`, plural `были сделаны` with `I`. | Quantity word taking singular (neuter-style) agreement. |
| `j` | Historical `although*jхотя`; grammar also creates silent clause boundaries with tag `j`. | Lowercase `j` does not universally mean “insert a comma” or “silent”: a lexical reading may contain printed text. |
| `p` | Historical `after*pРпослеDвпоследствииJ2после того, как`; grammar has `PL` → `p`. Case decoding is supported. Verified: with `p`, `After he came, we left` gives `После того, как он приходил`; with `P`, `После он приходил`. The original also picks the conjunction in `After the war he came` (`После того, как война`). | Preposition/conjunction word whose `J` reading is chosen before a clause. |
| `s` | `that` has a secondary `s, что`; grammar can change `A` + lexical `one` to `A s`. Initial lexical `s` normalizes to `S`. No dictionary reading starts with `s`; replacing `that`'s `s, что` with `S, что` changed none of the probes. | Context-generated substitute state; do not author it. |
| `w` | The `W` distributor creates `w` for an uninflected tail, e.g. the space before `помехи` in `WVсоздавать помехи`. | Distinct from uppercase `W`. Initial dictionary `w` is normalized differently; do not copy a runtime tail tag as a normal entry format. |
| `?` | Tokenizer's unknown alphabetic word, e.g. an unlisted English spelling. Can be tested in `Z[?#]`. | Internal fallback, not an uncertainty operator or a preferred authored class. |

There is no special lexical class definition for lowercase `o` or `q` in the
current decoder. `q` mentioned in older notes was a legacy future marker; the
production port does not implement it as a dictionary convention. Do not infer
support because the generic matcher can compare any byte.

Constituent tags/classes also reuse letters such as `W`, `w`, `K`, and `G` for
grouping. A constituent's `W` class is not an encoded `W` dictionary reading;
inspect the pipeline stage and field as well as the character.

Other runtime tag bytes are punctuation or structural states: `*`, space,
commas, periods, colons, semicolons, quotes, apostrophes, hyphens, `/`, parentheses,
braces, `&`, `+`, `^`, `=`, `_`, and `%`. For example, T2 rewrites `(#)` to `{#}`;
T4 can retag coordinating `C` or commas as `&`; a space tag marks a node for
compaction. Their downstream effects depend on the handler and pipeline stage.
Unresolved grammatical meanings must stay labeled unresolved; these bytes are
not regex operators or a menu of new lexical categories.

## Numeric values

### Field values

| Field | Values and scope | Example |
| --- | --- | --- |
| `number` | `0` singular; `1` plural. Some grammar states preserve other numeric values, while generation usually treats nonzero as plural. Author `0/1` unless an established rule requires another value. | `R021ты` versus `R12Вы`. |
| `person` | `1` first, `2` second, `3` third; `0` unset/nonfinite where applicable. | `X001` is present, singular, first person; `R031он` is singular, third person, masculine. |
| `gender` | `0` neuter, `1` masculine, `2` feminine; `#` also accepts Cyrillic `с/м/ж`. | `R032она`; `#0ж`. |
| `tense` | Verbs: `0` present, `1` past, `2` future. `d`/adjective comparison and `J` use the same storage for other stage-specific purposes. | `X103быть` is past, singular, third person. Do not interpret `J2` as future tense. |
| `aspect` | Verbs: `0` imperfective, `1` perfective. The field is overloaded: `P/R/M` use it for the prepositional pronoun prefix; `y1нет` marks a negative existential; other tags have specific control uses. | `PР01у` supplies prefix flag `1`, so third-person genitives can become `него/неё/них`. |
| `case_mask` / `governed_case` | Nominative `0`; genitive `2`; dative `4`; accusative `8`; instrumental `16` (`0x10`); prepositional `32` (`0x20`). These are masks, not case ordinals. | Cyrillic `Р` sets mask `2`. Generation maps it to internal case index `1`. |
| `verb_flags` | Bit mask: `1` participates in voice/reflexive handling; `2` conditional (`бы`); `4` imperative; `8` nonfinite/auxiliary-suppression handling; `16` appends interrogative particle `ли`. Complete linguistic role of every combination is not established. | T4 subrule selector `c` sets bit `2`; selector `5` also sets conditional bit `2` on the tail. |
| `passive`, `short_form` | Zero/nonzero voice and short-form state, set by grammar or morphology. Not free-standing dictionary tag suffixes. | T4 selector `a` sets `aspect=1, passive=1`. |

The six Cyrillic case letters are `И` nominative, `Р` genitive, `Д` dative,
`В` accusative, `Т` instrumental, `П` prepositional. Initial lexical case decoding
recognizes the five oblique letters, consumes only one, and also consumes `И`
without changing a preexisting mask. Later `senses.parse_code` recognizes `И`
as zero and can consume repeated case letters, with the last winning. Use one
explicit letter; do not depend on a later stage repairing an ambiguous prefix.

### Tag-specific positional layouts

Each field below consumes **at most one ASCII digit**, in order. A missing digit
does not reset the field: existing/default state remains. Put explicit digits
when inserted words would otherwise inherit inappropriate state. These are
English `.DIC` prefixes, not the packed binary `.RUS` format.

| Tags / path | Prefix layout after the tag | Example / caution |
| --- | --- | --- |
| `X`, `Y`, initial `x` | tense, number, person | `X001`, `X013`, `X003`; `Y003иметь`. `Y` also sets accusative. Later selected `x` readings consume only tense. |
| `R`, `M`, `r` | number, person, gender | `R011я`, `R021ты`, `R031он`, `R032она`, `R11мы`. `M` sets genitive; `r` does not by itself insert `у`. |
| Initial `O`, `S` | number, aspect/control, gender; person becomes 3 | `O01никакой`; historical `S1все` leaves subsequent fields at their defaults. Later selected `S` readings consume number/person/gender, then force person 3. |
| Initial `P`, `Q`, `f`, `p` | one optional Cyrillic case letter | `PВчерез`. Digits after that letter remain in the reading at this stage. |
| Selected `P`, `Q`, `p`, `O`, or `D` converted from `P` | case letter(s), number, aspect/control | W component `PР01у` is processed here: genitive, number 0, prefix flag 1. This is why checking only lexical output is insufficient. |
| `y` | aspect/control; sets genitive | `y1нет`; plain `yесть` leaves aspect unchanged. |
| `d` | aspect/control, tense/comparison state | Decoder example `d01выше` sets aspect 0 and comparison-state field 1; illustrative metadata example, not a historical entry. |
| `I` | number | Historical `I1много`. |
| `U` | tense, verb_flags; sets person 3 and accusative | Illustrative `U02должен`: present, conditional bit 2. Not an original-output claim. |
| Initial `J` | tense/control, aspect/control | Historical `J2после того, как`; greeting `J0` has empty text. Later selected `J` consumes a first control digit, and a second digit sets marker `k` rather than copying it as aspect. |
| `N`, `n` | one aspect/control digit; `n` additionally forces plural | Historical `ability*N1способность`: `1` sets the control field, not a paradigm ID. Prefer `nдело` for the greeting rather than a frozen plural spelling. |
| `v`, `z` | compact lookup-flags digit, lookup-aspect digit | Third person is set; `z` also sets plural. Both normalize to uppercase. These digits are lookup controls, not tense/number. |
| `V`, `Z`, `E`, `e`, `F`, `G`, `h` | compact lookup-flags digit, lookup-aspect digit, lookup-frame digit | Existing decoder fixture `V123делать` sets lookup flags/frame; the digits are **not** first person/plural/third tense. Fixture `E001Рслово` additionally records governed genitive when frame=1. |
| `#` | number, gender (digit or Cyrillic letter) | `#0м`, `#02`, `#0ж`; person becomes 3. Existing nonzero number is preserved by the initial decoder. |
| Other lexical tags | No general digit layout is implemented | Do not append imagined number/person fields to `A`, `B`, `C`, `K`, `T`, `m`, etc. |

The compact verb decoder preserves high flag bits: for first digit `d`, low
lookup flags receive `d` and bit `0x40` reflects `d & 1`; the second digit sets
lookup-frame bit `0x40` from its low bit; the third sets the frame's low six bits.
Thus `V123делать` yields `lookup_flags=0x41`, `lookup_frame=0x03` on a zeroed node;
preexisting `0x80` bits remain set. Russian declension/conjugation paradigms
come from morphology.

Observed effect of the historical verb digits (original LTPRO, with and without
the digits; see [verified findings](#verified-syntax-findings)):

| Digits | Historical verbs | Object + `to`-infinitive in the original |
| --- | --- | --- |
| none | most verbs | `I want him to come` with plain `Vхотеть`: `Я хочу его, чтобы придти`. |
| `2x` (`V21`, `G21`, `E21`, `Z21`) | want, wish, recommend, require | чтобы-clause with the object as subject: `Я хочу, чтобы он пришел`. |
| `1` (`V1`, `E1`, `G1`, `Z1`) | advise, acknowledge, admit, forecast | что-clause in the future: `Я советую, что он придет`. |
| second digit `1` (`V01`, `V11`, `E11`, `e11`) | allow, assist, agree, hope, let | Bare infinitive: `Они позволяют ему идти`, `Я понадеялся приходить`. |
| `U1`, `U12` | could, might | Conditional `мог бы`; plain `U` gives present `может`. |

The trailing case letter of `E001В`, `E011Д` names the object case; removing the
digits from `asked`/`helped` changed nothing because the Russian record already
governs the case. Copy these digits from a comparable historical verb rather
than composing new values.

## Dictionary punctuation

A record is one per key and packs every reading:
`PREFIX SEGMENT {SEGMENT} [\stem]`. The prefix is the English word's class plus
its verb digits (`V11`, `Z01`). Each segment is a class letter, optionally
dotted, followed by meanings separated by `;` (`table*NN.стол{…};инф)таблица{…}A.табличный`).
The first meaning is the translation, and the rest print inline as `{1.…}`. A
segment of another class is a grammatical reading that grammar may choose, not
a listed meaning. The full grammar and LTGOLD examples are in
[docs/dictionary.md](../../../docs/dictionary.md#record-structure-one-record-per-key-one-segment-per-part-of-speech).

| Syntax | Meaning | Example |
| --- | --- | --- |
| `key*reading` | Lookup key / encoded reading separator. | `economy*Nэкономика`. |
| `key*=other-key` | Whole-record redirect, resolved before ordinary decoding; cycles raise an error. | Historical `welch*=welsh`. Distinct from a transliteration macro following a tag. |
| `;` inside reading | Alternative meanings, primary first; selected meanings can have annotations. | `Nэкономика;экономия`. Does not create a new grammatical class. |
| `{...}` inside reading | Annotation or domain information attached to a meaning. | Historical `N.реферат{synopsis}` in `abstract`. Not a matcher capture. |
| `\stem` at end of lexical reading | Backreference for stem lookup/derived forms and stem phrase/subrule lookup. | `crossed*Eпересекать\cross`. Not a general substitution command. |
| `W` | Introduce composite Russian equivalent. For single-word inputs, native encodings precede it with the input class and the reading's class. | `afterclap*NNWAнеприятноеNсобытие` = input class `N`, then reading class `N` for `WAнеприятноеNсобытие`, like `N.` in a packed reading. Verified: `NWA…` loses the first component (`Событие было плохим`) and `WA…` breaks the reading. Keep both letters (`NNW`, `AAW`, `EVW`, `GVW`, `ZVW`). |
| `,` before a component tag | Literal comma printed before that component. | `aborticide*NNWNсредство ,Aвызывающее аборт` gives `Средство, вызывающее аборт`; without the comma, no comma. |
| `word*:` | Phrase-head placeholder: the word only starts multiword keys. Alone it stays an untranslated unknown word with no suffix analysis. | Historical `corned*:` beside `corned beef*Nсолонина`: `Corned is good` gives `Corned хорошее`. Deleting `corned*:` makes the original stop finding `corned beef`; Lua finds phrases without it. |
| `\|` as a reading's class | Fixed separator class, not an adverb. | `faster than*\|быстрее чем`: `Это - быстрее чем свет`; as `D`: `Это быстрее чем светлый`. |
| `label)` before a meaning | Domain label, such as `инф)` computer, `дел)` business, `мес)` month, `штт)` US state. | `admission*Nдопущение;инф)доступ`. The label is never printed. `инф)`/`дел)` meanings are promoted only by `/AM` with COMPUTER or BUSINESS second in `/C` (Lua `--domain`); other labels serve `!мес!`-style text tests. |
| Adjacent component tags | Start separately analyzed/agreed output components; no inter-tag spaces required. | `WAпослепродажныйNсервис`. |
| Space in a `W` payload | Start an uninflected tail. Appropriate only for text that should stay fixed. | Space before `помехи` in `WVсоздавать помехи`. It is not needed between `Dкак` and `nдело`. |
| `/` in packed reading | End a phrase reading / delimit another tagged reading. | `bond*ZWVподписывать обязательство/Nобязательство;облигация`. |
| `A.`, `N.`, `V.` etc. | Explicit input-side classification in a compound/ambiguous reading. | `executive*NNWAдолжностноеNлицо/A.исполнительный`. Not a sentence terminator. |
| `~` in literal phrase key/output | Native manual: arbitrary word position. Lua: bounded gap of zero or more word records, stopping at punctuation/protected spans; output `~` reinserts the capture. | Native `on ~ account*WPВза~Nсчет`. Not a typed pronoun placeholder. |
| `#` component | Native proper name/nontranslated component, optionally with metadata. Lua also supports delimited `#...#` literal spans. | Historical `article i*WNстатья#I`; never use `W#как дела#` to avoid coding Russian words. |
| `=` / `%` following a tag | Transliteration macro. `=` honors the transliteration option; `%` forces it. Supplied Cyrillic spelling after the macro replaces the transliteration. | Historical `abbott*#0м=` gives `Абботт`; `aeneas*#0м=эней` gives `Эней`. Historical `abe*#0m=эйб` has a Latin `m`, which stops the macro: the original prints `Abe`. Multiword names keep each English word's capital (`Буэнос Айрес`). Distinct from whole-record `*=key`. |
| `\|` between verb readings | Select the right-hand alternative when runtime aspect is 1, otherwise the left-hand reading. | Illustrative `Vчитать\|прочитать`; not a new phrase-component separator. |
| Final sentence punctuation | Not part of a native literal phrase key. Use `[*]` in a grammatical context rule to require sentence end. | BASE.DIC ``thank `you`[*]*$Dблагодарю вас\ \``. The former Lua-only punctuation-key matcher has been removed. |

## Context patterns and actions

`head pattern*$action` attaches a context subrule to the head. The space after
the head is required syntax. The pattern starts at the **following word**, not
at the head. The final `*$` separates key from action; the `*` in `[*]` is part
of the pattern. Subrules are collected separately from literal phrase keys.

### Lexical context matcher

These are the operations supported by `core/matching.lua` on lexical nodes.
They test **current tags**, not all secondary readings inside a dictionary value.
Do not write regex syntax. Span searches use a cached tag string and the first
anchor found; a later failure does not retry another anchor.

| Pattern | Meaning and example |
| --- | --- |
| `XR` | Consume two nodes: auxiliary `X`, then personal pronoun `R`. |
| `[MR]` | Consume one node of either class. `R/M` is not alternation syntax. |
| `[*]` or `*` | Consume a real boundary-tag node. In the greeting's final position, require sentence end; neither is a repetition operator or zero-width regex anchor. |
| `~R`, `~[MR]` | Negate the next test. Here `~` is not the literal-phrase gap syntax. |
| Backticked word | Test source spelling ignoring ASCII case, or exact lookup spelling. Historical ``in `full`[*]*$Dполностью\ \`` tests `full` after `in`. |
| `!мес!` | Test whether the node's stored reading contains `мес)`; the closing parenthesis is appended by the matcher. Not a literal English word test. |
| `<D>V` | Search first following `V`; require every intervening cached tag to be `D`. Empty spans are allowed. |
| `<DA>[VN]` | Search first `V/N` anchor and restrict intervening tags to `D/A`. |
| `<$>V` | Search first `V` anchor without restricting intervening tags. |
| `<D>` followed by a backticked word or `!text!` | Same span restriction, anchored by a lexical/text test. |
| `[$]` | Consume any one lexical node. |
| Bare `$` | Try the remaining pattern at the current node, then after skipping exactly one node if needed; e.g. `$R`. Not an arbitrary-length wildcard. |
| Alternatives inside `[]` or `<>` | Lua lexical matcher accepts classes plus backticked word / `!text!` choices. E.g. ``[R`thou`]`` accepts `R` or lexical `thou`. Advanced feature: native parity is not established by this reference. |
| Punctuation classes | A punctuation token is its own tag: `%` (``from <H%>`to` ``), `(`, `)`, `:`, `"`/`'` (escaped `\"`/`\'` inside a class), `,` and `*`. `_` is a word starting with an underscore (`state [?#_]`), `^` a boundary T4 inserts before a preposition, `{` `}` T2's rewrite of `(#)`. Only ASCII matches: the Cyrillic `С` in historical ``in `writing`[,С*]`` is a typo that never matches `C`. |

In the **constituent** matcher, `.` consumes one constituent, while bare `$`
and `[$]` are ordinary tag/class tests. Lexical alternatives are not uniformly
available in constituent views. Do not transfer lexical patterns there blindly.

### Native subrule actions (T4)

Ordinary native subrules are **head rewrites**, not a W template automatically
distributed over the entire match. Their format can be
`head pattern*$head-action\tail-action\selector`. The first backslash-delimited
part rewrites the head; the second uses `matching.replace` on matched context;
the first character after the second backslash selects special handling.
Everything after that character is ignored, including further backslash
sections. Verified: ``bear <TAONMw>`in`<AO>`mind`*$Vиметь\$`Dв`\$`Dвиду` ``
never produces `виду`; moving `` $`Dвиду` `` into the tail action does. Seven
historical rules carry such dead sections (`bear`, `ask`, `cause`, `make up`,
`prevents`, `a few`, `as far as`). Put every context edit in the tail action.

The head action's first tag byte changes its class. A leading `?` or `@` keeps
the class, and a leading Russian letter begins replacement text without changing
class. No supplied text leaves existing reading text in place. For example,
historical `as RV*$Jкогда` changes `as` to `J` with reading `когда`.

| Tail-action atom | Operation / example |
| --- | --- |
| `N`, `V`, other ordinary byte | Save previous tag, write new current tag. This does not itself invent/select a translation. |
| `@` | Keep the node and its previous tag. |
| `.` | Keep/advance one aligned node with pattern-aware handling. Not interchangeable with `@` in every span branch. |
| Space | Retag for later compaction. Not a printed output space. |
| `$` | Align actions to the pattern's next span anchor. |
| Backticked `Pк` | Set tag `P` and reading `к`. |
| Backticked `@к`, `?к`, or a Russian-leading payload | Keep tag and replace only reading text. |

Alignment follows matcher atoms, not raw pattern character count. `[VN]` is one
node. Short actions leave trailing context intact. The original literal loop
limits a backticked replacement to 80 bytes. Plain-tag anchors after `$` have
special advancement rules for `@` and backticked payloads; consult
`core/matching.lua` before creating complex edits.

Recognized T4 subrule selector characters, from `core/phrasing.lua`:

| Selector | Effect | Example |
| --- | --- | --- |
| absent | No selector-specific handler. | Historical `as RV*$Jкогда`. |
| `1` | On node before match end: aspect=0, passive=0, tense=0. | Historical `want <AOIHNw\"\'>[Ee][;:*]*$?\$V\1`. |
| `2` | Apply only if final matched node has nonzero number. | Verified: ``a `few`N*$?\`Iмного`\2`` gives `Много книг` for `A few books` but leaves `A few book` alone. Historical `\?\2` reads selector `?`, so its `2` does nothing. |
| `3` | Head aspect=1. | Historical `began G*$V\V\3`. |
| `4` | Sentence-initial head person=1; change head `G` to `V`. | Historical ``look `forward`*$Vожидать\ \4``. |
| `5` | Remove head; tail case=8, tense=1, conditional flag bit 2 set. | Historical ``would <dDK>`like`*$?\$`Vхотеть`\5``. |
| `6` | Head case=dative. | Historical `afford [MR]*$Vпозволять\M\6`. |
| `7` | Set tail marker `n` (participle-related). | Historical `once E*$PТбудучи\E\7`. |
| `8` | Empty tail reading; if tail is `P`, set dative case. | Historical ``help `to`*$?\@\8``. |
| `9` | Apply only when previous node is `X`. | Historical `final [,C*]*$Aконечный\.\9`. |
| `a` | Tail aspect=1, passive=1. | Historical `being E*$ \A\a`. |
| `c` | Set head conditional flag bit 2. | Historical `could V*$@\@\c`. |
| `f` | Head reading_state=0. | Historical `fortune H*$@\@\f`. |
| `g` | Set tail marker `g`. | Historical `when <\"\'>G*$PПпри\$N\g`. |
| `h` | Tail aspect=1. | Historical `having E*$ \g\h`. |
| `n` | Apply only if head is not currently `N`. | Historical `notice [TAO]*$замечать\\n`. |
| `r` | Head passive=0, tense=0. | Historical `run [TAONIH\"\']*$Vвыполнять\\r`. |

Any other selector character has no handler in the original either: `N`, `V`,
`$`, `?` and space behave as no selector (verified for `N` and `V`). Avoid them.
Handler numbers in extracted grammar tables T1–T8 are a separate namespace,
not these selector characters and not dictionary grammatical digits.

## Greeting entries

```text
how XR[*]*$Dкак\`PР01у``MMWMJ0nдело`\
what <X>`up`[*]*$DDWDкакnдело\ $ \
```

### Native grammatical rule for “how are you”

| Fragment | Meaning |
| --- | --- |
| `how` | Dictionary head, with its ordinary lexical entry `how*Qкак`. |
| Space after `how` | Separates the head from its grammatical context pattern. |
| `X` | Auxiliary be: am/are/is, classified structurally. |
| `R` | Personal pronoun, matched by tag rather than English spelling. |
| `[*]` | Sentence boundary. Excludes `How are you feeling?`; does not require a particular final punctuation mark. |
| `*$` | End context key / begin encoded subrule action. |
| `Dкак` | Replace the head class and reading with adverb `как`. |
| First backslash | Start the context replacement action. |
| Backticked `PР01у` | Replace the auxiliary with preposition `у`; Cyrillic `Р` requests genitive, `0` sets number, `1` sets the pronoun-prefix flag. |
| Backticked `MMWMJ0nдело` | Replace the pronoun's class and reading while keeping its original grammatical fields. First `M` sets the class; the remaining `MWMJ0nдело` is its packed equivalent. |
| `MWM` | Packed pronoun-class composite with an empty initial `M` component. The existing number/person/gender fields drive oblique pronoun generation; it does not copy an English spelling or hardcode a Russian form. |
| `J0` | Empty separator with first control digit 0. Closes the prepositional group so the following noun does not inherit genitive. |
| `nдело` | Noun lemma `дело`, plural. Normal morphology produces nominative `дела`. |
| Final backslash | Start an empty selector section. |

This uses native T4 context replacement and later W expansion. It was executed
in original LTPRO using isolated experimental dictionaries; it is a newly
authored rule, not an entry claimed to exist in historical BASE.DIC. Original
LTPRO generates `Как у Меня дела?`, `Как у Вас дела?`, `Как у его дела?`,
`Как у ее дела?`, `Как у нас дела?`, and `Как у их дела?`. Lua applies phrase-wide
casing and the corrected prepositional pronoun prefix, giving `меня/него/неё/них`.
The default curated dictionary selects informal singular `ты` for `you`.
Contraction expansion lets `How's he?` use the same rule.

A later native T4 rule rewrites sentence-final English `it` to `Rэто`, overriding
the pronoun composite: original `Как У Это?`. Lua preserves authored W components
against English lexical rewrites wholly inside the same equivalent, producing
`Как у него дела?`. This is a general phrase-ownership correction, not a special
translation of the spelling `it`; tag-based agreement still runs. The complete
curated capture and regression include this pronoun and its contraction.

### Native boundary rule for “what’s up”

```text
what <X>`up`[*]*$DDWDкакnдело\ $ \
```

| Fragment | Meaning |
| --- | --- |
| `what` | Head word whose native T4 subrule is attached during lexical analysis. |
| `<X>` | Span of auxiliary `X` nodes before the lexical anchor. May be empty: the original question-cleanup pass removes present `is` before T4. |
| Backticked `up` | Require this English source/lookup word. |
| `[*]` | Require the final boundary node, excluding `What is up there?`. |
| `*$` | End context key / begin subrule action. |
| First `D` | Change the head's class to adverb. |
| Second `D`, then `W` | Packed adverb-class composite reading, following native repeated-class conventions such as `exclusive [*]*$VVWKнеVучитывать`. |
| `Dкак` | First Russian output component. |
| `nдело` | Plural noun generated from lemma `дело`. |
| First backslash | Separate the head rewrite from the context replacement action. |
| Space, `$`, space | Delete the initial context node, align with the `up` anchor, and delete that node if still present. When question cleanup already removed `is`, the first deletion consumes `up` and no later node is deleted. |
| Final backslash | Start an empty selector section; no extra selector handler. |

Exact historical BASE.DIC models:

```text
thank `you`[*]*$Dблагодарю вас\ \
in `full`[*]*$Dполностью\ \
exclusive [*]*$VVWKнеVучитывать
```

The idiom rule was tested in isolated copies with original LTPRO: it matches
`What is up?`, `What's up?`, a spaced input question mark, a period, an exclamation
mark, and no final punctuation. It excludes longer `What is up there?` and
`What is up with him?`. The original output is `Как Дела?` for title-case input;
Lua uses the same rule with phrase-wide sentence casing, producing `Как дела?`.
Lowercase input produces `как дела?` in both. The original lexical test also
recognizes a one-word protected source spelling, as in `What's {~up~}?`.

Do not replace `[*]` with a literal `?` or put a second bare `*` into a literal
phrase key. The original dictionaries' boundary examples are grammatical
subrules, and a star in such a pattern is separate from the entry separator.
Native short-question support must be investigated before adding matcher syntax.

### `.RUS` code bits

Byte 2 of a Russian record (after the class letter) carries flags. Flipping one
bit in an isolated copy of LTGOLD's `BASE.RUS` gave:

| Class | Bit | Verified effect | Example |
| --- | --- | --- | --- |
| `V` | `0x08` | Future is analytic `буду` + infinitive, ignoring any partner. Without it, a verb with no partner uses its own present as the future. | работать `e8`: `Я буду работать`; cleared: `Я работаю`. видеть with `0x08`: `Я буду видеть его`. |
| `V` | `0x02` | Set on native perfectives (увидеть `e3`, помочь `e2`). Lua skips the partner lookup for it. | Clearing it on увидеть changed nothing. |
| `V` | `0x04` | Lua forces perfective aspect when `0x08` is clear. Native: прийти `a6`, быть `e4`. | Setting it on увидеть changed nothing. |
| `A` | `0x20` | Short form everywhere, including attributive. | рад `a0`: `Он рад`, `Рад человек`; cleared: `Он радый`. |
| `A` | `0x01` | Short form as a present predicate after a noun or pronoun; instrumental long form in the past. | рад `81`: `Человек рад`, `Он был радым`, `Радый человек`. |

LTGOLD's `BASE.RUS` has no record for глубокий, and the original prints
`Река глубока` (but `Дом большой`); what selects that short form without a
record is not isolated.

### Program switches

`/AM` with `/C cu` (computer) or `/C bu` (business) promotes `инф)` or `дел)`
meanings: `Доступ`, `Драйвер`, `заземление`, or `Последователь`,
`Инкассирование`. Without `/AM`, or with only the base dictionary, the primary
meaning stays. The original drops the first letter of a demoted unlabelled
primary (`Доступ{1.опущение}`); Lua keeps it. `/L-`, `/MM` and `/SM` do not
change batch output: inline `{1.…}` alternatives are on in the supplied profile.

### Reviewed deliberate differences

Rechecked against the original with the current default dictionaries:
`Let's go.` is `Давайте идти` there, `Давайте пойдем` here; `Will he come?`
is present `Он приходит?` there, future `Он придет?` here; `How is it?` is
`Как У Это?` there because a later English rule rereads `it`, while Lua
protects authored phrase components (`Как у него дела?`).
